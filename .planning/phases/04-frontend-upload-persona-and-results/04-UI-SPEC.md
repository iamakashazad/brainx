## Spacing Scale

Declared values (multiples of 4, 8-point base):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline chip padding, tab indicator gaps |
| sm | 8px | Compact element spacing, button icon-text gap, form field gap |
| md | 16px | Default element spacing, card padding, form input padding |
| lg | 24px | Section padding, wizard step content padding |
| xl | 32px | Layout column gaps, major card padding |
| 2xl | 48px | Wizard step transitions, results panel sections |
| 3xl | 64px | Page-level vertical rhythm |

Exceptions:
- Touch targets for icon-only buttons (preset view buttons, circuit toggle): minimum 44px hit area (inner content may be 24px icon; add padding to reach 44px).
- 3D brain canvas: height is 60–70% of viewport (`60vh` minimum); not governed by the spacing scale.
- Timeline scrubber handle: minimum 44px touch target height even at compact visual size.

## Typography

Two weights only: 400 (regular) and 600 (semibold).

| Role | Font | Size | Weight | Line-height | Usage |
|------|------|------|--------|-------------|-------|
| Body | Inter (sans) | 16px | 400 | 1.5 | Paragraph copy, form labels, recommendation text |
| Label / Caption | Inter (sans) | 14px | 600 | 1.4 | Field labels, nav step labels, badge text, tab labels |
| Heading | Inter (sans) | 20px | 600 | 1.3 | Card headings, section titles, panel headings |
| Display | Inter (sans) | 28px | 600 | 1.2 | Page-level headers (e.g., "Results"), wizard step title |
| Numeric readout | Roboto Mono (mono) | 14px | 400 | 1.4 | ROI scores, circuit activation values, queue position |
| Numeric large | Roboto Mono (mono) | 20px | 600 | 1.3 | Primary score readout, top-level activation percentage |

Notes:
- Lora (serif) is declared in the token file but reserved for future display use; do not use in Phase 4 components.
- All font sizes are in `px` in this contract; use `rem` equivalents in code (`16px = 1rem`, `14px = 0.875rem`, etc.).
- `04-DESIGN-TOKENS.css` defines font-family tokens only; no weight variables are set in the token file, so no CSS changes are required there.

## Color

All color values reference tokens from `04-DESIGN-TOKENS.css`. The `.dark` values are the runtime defaults.

| Role | CSS Variable | Dark Value | Usage |
|------|-------------|------------|-------|
| Dominant (60%) | `--background` | `oklch(0.21 0.02 226.02)` | Page background, full-screen progress view backdrop |
| Secondary (30%) | `--card` | `oklch(0.23 0.03 218.18)` | Cards, wizard step panel, persona library list, recommendation panel |
| Sidebar / Nav | `--sidebar` | `oklch(0.19 0 0)` | Sidebar background if used, wizard sidebar nav |
| Accent (10%) | `--primary` | `oklch(0.72 0.12 210.36)` | See reserved list below |
| Muted surface | `--muted` | `oklch(0.18 0.02 227.33)` | Skeleton loaders, disabled inputs, empty state backgrounds |
| Destructive | `--destructive` | `oklch(0.64 0.21 25.39)` | Delete persona confirmation, clear form destructive actions |
| Border | `--border` | `oklch(0.36 0.02 213.25)` | Card borders, dividers, input borders |
| Foreground | `--foreground` | `oklch(0.81 0.04 226.14)` | Default body text |
| Muted foreground | `--muted-foreground` | `oklch(0.58 0.03 223.55)` | Placeholder text, helper text, disabled labels |
| Ring | `--ring` | `oklch(0.72 0.12 210.36)` | Focus rings on all interactive elements |

Accent (`--primary`) reserved for:
1. Active wizard step indicator (the numbered circle for the current step)
2. Primary CTA buttons: "Analyze Content", "Save Persona", "Create Persona", "Next"
3. Selected persona card border/highlight in the persona library
4. Active circuit selector button (the currently-displayed circuit)
5. Timeline scrubber thumb and fill track
6. Focus ring (via `--ring` which mirrors `--primary`)
7. Recommendation pill hover underline / active indicator when rec is clicked and brain highlights

Accent is NOT used for: body text, card surfaces, nav backgrounds, score bar fills (those use `--chart-1`–`--chart-5`).

Chart tokens for data viz:
| Token | Dark Value | Assignment |
|-------|------------|------------|
| `--chart-1` | `oklch(0.72 0.12 210.36)` | Circuit 1 bar gradient / vertex overlay color |
| `--chart-2` | `oklch(0.79 0.12 209.45)` | Circuit 2 |
| `--chart-3` | `oklch(0.76 0.11 208.70)` | Circuit 3 |
| `--chart-4` | `oklch(0.83 0.10 208.33)` | Circuit 4 |
| `--chart-5` | `oklch(0.57 0.10 213.73)` | Circuit 5 |

Chart bars use a left-to-right gradient from `--chart-N` at 100% opacity to 40% opacity at the right edge. Animated fill on mount (grow from 0 to full width, 400ms ease-out).

60/30/10 split in practice:
- 60% `--background`: full-page canvas, modal overlays, progress view backdrop
- 30% `--card`: persona cards, content upload panel, recommendation panel, score cards
- 10% `--primary` accent: CTAs, active states, and the 7 reserved elements above

## Component Inventory

The following components must be authored for this phase. All consume tokens; no color literals.

### Wizard Shell
- `WizardStepper` — 4 steps (Persona / Content / Run / Results); free navigation between completed steps; state indicator per step (inactive / active / complete); horizontal or vertical layout at implementor discretion; step labels in Label style (14px/600).
- `WizardStep` — container component that wraps each step's content area with `--card` background, `--shadow-lg`, and standard `lg` (24px) padding.

### Persona Step (Step 1)
- `PersonaLibrary` — grid/list of saved personas from `GET /personas`; each card shows name, demographic summary, and a "Use this persona" button; selected card highlighted with `--primary` border.
- `PersonaCard` — individual card with tilt/lift hover (Figma/Framer aesthetic: `transform: scale(1.02) rotate3d(0,0,0,1deg)` on hover, 150ms ease); `--shadow-md` at rest, `--shadow-xl` on hover.
- `PersonaForm` — tabbed form with 4 tabs: Demographics / Psychographics / Cognitive State / Environment; tab progress indicator shows completion state; hits `POST /personas` on save.
- `PersonaTabProgress` — 4-dot or 4-segment indicator above or within the tabbed form showing how many tabs have been filled.

### Content Step (Step 2)
- `ContentTypeTabs` — 3 tabs: Text / UI Screens / Static Image; 1:1 mapping to backend endpoints.
- `TextInput` — textarea for `POST /content/text`; 16px body text; placeholder in `--muted-foreground`.
- `ScreenUploader` — drag-and-drop zone accepting 1–5 images for `POST /content/screens`; shows thumbnail previews with remove controls; file count badge.
- `StaticUploader` — single-image drag-and-drop for `POST /content/static`; thumbnail preview.
- `UploadDropZone` — shared base component for ScreenUploader and StaticUploader; dashed `--border` outline; `--muted` background; icon + label center; `--primary` outline on drag-over.

### Progress View (Step 3 / Run)
- `ProgressView` — full-screen, non-dismissable; `--background` fill; centered layout.
- `StageIndicator` — 5-stage vertical or horizontal stepper: PENDING → SIMULATING → INFERRING → AGGREGATING → COMPLETE; active stage highlighted with `--primary`; completed stages with checkmark.
- `QueueBadge` — "Position N in queue" displayed in Roboto Mono 14px/400 using `--muted-foreground`; hidden when queue_position is 0 or null.
- `ProgressSummary` — optional side panel (Claude's discretion) showing persona name + content thumbnail while job runs; uses `--card` surface.

### Results View (Step 4)
- `ResultsLayout` — split layout: brain canvas 60–70% of viewport width (or height on narrow), recommendations panel filling remainder.
- `BrainCanvas` — `@react-three/fiber` canvas; fsaverage5 mesh; `MeshStandardMaterial` matte; ambient occlusion; per-vertex color overlay driven by active circuit's Float32 array; `OrbitControls` enabled.
- `BrainPresetButtons` — 4 buttons: Lateral-L / Lateral-R / Superior / Anterior; icon or short label; 44px touch target; `--card` background, `--primary` on active/focus.
- `CircuitSelector` — toggle/button group for 5 circuits; active circuit highlighted with `--primary`; circuit names from backend `ScreenROI.circuits`; default = highest-scoring circuit for this job; Roboto Mono 14px labels.
- `TimelineScrubber` — horizontal scrubber with one tick per uploaded screen; auto-plays once through all screens on results load (settles on final screen); scrubbable after; `--primary` thumb and filled track; 44px touch target height.
- `ROIScoreTable` — named-region score table; Roboto Mono 14px for score values; `--card` background; alternating `--muted` row tint.
- `CircuitScoreBar` — animated gradient bar (chart tokens); height 20px; label 14px/600 Inter; value Roboto Mono 14px/400; grows from 0 to score value on mount (400ms ease-out).
- `RecommendationsPanel` — scrollable list of recommendations; each item is a `RecommendationCard`.
- `RecommendationCard` — `--card` background; tilt/lift hover; clickable — on click highlights referenced region on BrainCanvas and scrubs to referenced screen; primary evidence location jumped to; secondary locations marked as small dots on timeline; clicking same card again cycles through all referenced locations.
- `FlowContinuityChart` — line/area chart showing cognitive load and emotional engagement across screens; chart tokens for fill; mounted with draw-on animation (left to right, 600ms).

## Motion Contract

Rich/cinematic motion as specified in D-23. All durations in milliseconds.

| Interaction | Animation | Duration | Easing |
|-------------|-----------|----------|--------|
| Brain first load (results mount) | Vertices fade in with staggered opacity 0→1, scale 0.8→1.0 | 800ms total, 50ms stagger per region cluster | `cubic-bezier(0.16, 1, 0.3, 1)` (spring-out) |
| Circuit swap (toggle new circuit) | Per-vertex color morphs across the mesh | 400ms | `ease-in-out` |
| Timeline scrubber auto-play (on load) | One pass through all screens, 600ms per screen | N × 600ms total | `ease-in-out` per screen |
| Stage transition in progress view | Fade+slide next stage in from below | 300ms | `ease-out` |
| Persona card hover | `scale(1.02)` + `--shadow-xl` | 150ms | `ease-out` |
| Recommendation card hover | `scale(1.01) translateY(-2px)` + `--shadow-xl` | 150ms | `ease-out` |
| Rec click → brain highlight | Region pulses (scale 1.0→1.05→1.0) | 500ms | `ease-in-out` |
| Chart bar fill on mount | Width 0→value% | 400ms | `ease-out` |
| Flow continuity chart draw | SVG stroke-dashoffset draw | 600ms | `ease-in-out` |
| Wizard step transition | Crossfade + slide next step in from right | 250ms | `ease-out` |
| Progress view → results auto-transition | Fade out progress, fade in results | 400ms | `ease-in-out` |

Reduced motion: all durations collapse to 0ms when `prefers-reduced-motion: reduce` is detected. Opacity fades may remain at 150ms as they do not trigger vestibular sensitivity.

## Interaction Contract

### Wizard Navigation
- Steps: Persona (1) → Content (2) → Run (3) → Results (4).
- Free navigation between completed steps via stepper; uncompleted future steps are non-clickable.
- Form state persisted to `localStorage` key `brainx-wizard-state`; restored on page refresh.
- "Next" button is `--primary` filled; "Back" is ghost/outline.
- Active step indicator uses `--primary` filled circle; completed step uses checkmark icon in `--primary`; future step uses neutral `--border` circle.

### Persona Library
- Default view on step 1: persona list from `GET /personas`.
- If list is empty: empty state (see Copywriting Contract).
- "Create new persona" button opens `PersonaForm` in a slide-over or inline expansion.
- Selecting a persona highlights card with `--primary` border and enables "Next" on the wizard.
- Delete persona: trash icon on card → inline confirmation tooltip (not a modal for Phase 4); uses `--destructive` color.

### Content Upload
- Tabs default to "Text" on first visit (simplest path).
- For UI screens: thumbnails shown immediately after file selection; each thumbnail has an ×-remove button (44px target); file count "2/5 screens added" shown as `--muted-foreground` caption.
- For any upload tab, the "Next" / "Analyze Content" CTA is disabled until the tab's required input is present.

### Progress View
- Full-screen; no way to navigate away during run (browser back is allowed by the OS but not surfaced in UI).
- `StageIndicator` advances in real time as `GET /jobs/{id}` returns updated stage.
- `QueueBadge` shows queue position when > 0.
- On `COMPLETE` status: auto-transition to results view after a 0ms delay (immediate).
- On `FAILED` status: show error state (see Copywriting Contract); offer "Try again" (re-submits) and "Go back" (returns to wizard step 2).

### 3D Brain Interaction
- Mouse drag / touch drag: free orbit via `OrbitControls`.
- Preset buttons: animated camera tween to preset pose (400ms `ease-in-out`).
- Click on brain region: no action in Phase 4 (reverse linkage from brain to recs is deferred per D-10 which specifies one-way: rec → brain only).
- Circuit selector: single active circuit at a time; switching triggers color morph animation.
- Timeline scrubber: drag or click to jump to screen N; brain vertex data reloads for that screen index.

### Recommendation Linkage
- Clicking a `RecommendationCard`:
  1. Scrubber jumps to the primary referenced screen (strongest evidence).
  2. Brain highlights the primary referenced region (pulse animation).
  3. Secondary referenced screens/regions are marked with small dots on the timeline and a subtle ring on the brain mesh.
  4. Clicking the same card again cycles to the next secondary location.
- Active recommendation card shows `--primary` left border.

## Accessibility Contract

- All Radix UI primitives used for interactive elements (tabs, dialogs, tooltips, toggle groups) to guarantee ARIA roles and keyboard navigation.
- Focus ring: `--ring` token at 2px offset on all interactive elements.
- Color contrast: foreground/background pairs must meet WCAG AA (4.5:1 for body text, 3:1 for large text). Dark theme values in `04-DESIGN-TOKENS.css` are pre-validated for this.
- `OrbitControls` canvas: provide screen-reader accessible label "Interactive 3D brain activation map. Use preset view buttons to navigate."; preset buttons are keyboard-focusable with arrow key support.
- `TimelineScrubber`: implement as `<input type="range">` base (Radix Slider or native) for keyboard accessibility.
- All form fields have explicit `<label>` associations (not just placeholder text).
- `ProgressView` traps focus while non-dismissable (ARIA live region announces stage changes).
- Reduced motion: `prefers-reduced-motion: reduce` collapses all durations as specified in Motion Contract.
- All icon-only buttons (BrainPresetButtons, persona-card trash) MUST carry an explicit `aria-label` describing the action (e.g., `aria-label="View: Lateral Left"`, `aria-label="Delete persona: {name}"`).
