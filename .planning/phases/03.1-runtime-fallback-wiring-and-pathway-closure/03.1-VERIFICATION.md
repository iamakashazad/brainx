# Phase 3.1: Runtime Fallback Wiring and Pathway Closure Verification Report

**Phase Goal:** The shipped `/analyze` pipeline can switch into the slideshow/video fallback path when required, and `SIM-03` is proven in the real runtime flow rather than only in isolated services/tests
**Verified:** 2026-04-18T18:17:16Z
**Status:** pass
**Re-verification:** Yes - this report closes the post-audit runtime evidence gap opened by `v1.0-MILESTONE-AUDIT.md`

## Goal Achievement

Phase 3.1 now satisfies its runtime closure goal:

1. `backend/core/queue.py` consults the runtime pathway decision instead of forcing all `/analyze` jobs through per-screen text inference.
2. Eligible visual analyze jobs can build `activations/{job_id}/fallback_slideshow.mp4`, call `run_tribev2_video()`, split the activation timeline back into per-screen `screen_{n}.npy` files, and continue through the existing Phase 3 ROI and recommendation pipeline.
3. Focused `/analyze` regressions now fail red if visual content stops reaching the video path, if text content incorrectly switches to video, or if a short video activation is reported as success.

## Evidence

- Before Phase 3.1, the milestone audit correctly found that `backend/core/queue.py` always ran per-screen `run_tribev2_text()` and never consulted pathway configuration for shipped `/analyze` jobs.
- After `03.1-01`, the shared worker resolves `selected_pathway = resolve_runtime_pathway(content)` and routes eligible visual jobs through slideshow generation plus `run_tribev2_video()` in `backend/core/queue.py`.
- `tests/test_analyze.py::test_analyze_uses_video_fallback_for_ui_screens` drives the public `POST /analyze` route with `ui_screens` content and `set_default_pathway("video")`, patches `create_slideshow()` to emit `activations/{job_id}/fallback_slideshow.mp4`, asserts `run_tribev2_video()` is awaited once, asserts `run_tribev2_text()` is not used for inference, and verifies the finished payload records the selected runtime path under `result.pathway.selected_pathway == "video"`.
- The same regression verifies the shipped artifact contract remains intact: the response references `activations/{job_id}/fallback_slideshow.mp4` and the worker still writes `screen_1.npy`, `screen_2.npy`, and `screen_3.npy`.
- `tests/test_analyze.py::test_analyze_keeps_text_path_for_text_content_when_video_is_default` proves text content stays on the text path even when the default pathway is `video`; `run_tribev2_video()` is never called and the finished payload reports `result.pathway.selected_pathway == "text"`.
- `tests/test_analyze.py::test_analyze_video_fallback_split_failure_errors` proves the worker fails closed when `run_tribev2_video()` returns too few timesteps to split across all simulated screens. The job ends in `ERROR` and never exposes a misleading success payload.
- `tests/test_analyze.py::test_legacy_test_inference_single_shot` still passes, confirming the legacy Phase 1 `/test-inference` path remains isolated from the shared `/analyze` fallback wiring.
