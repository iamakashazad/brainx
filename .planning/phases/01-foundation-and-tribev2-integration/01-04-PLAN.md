  <action>
The root cause: TRIBEv2 inference stalls on Apple Silicon MPS device. The research explicitly recommended CPU fallback if MPS fails. The fix has three parts:

**Part A — Change default device to CPU in config and .env:**

1. In `.env`, change `DEVICE=mps` to `DEVICE=cpu`
2. In `backend/core/config.py`, change the default from `device: str = "mps"` to `device: str = "cpu"` so that the default matches even without .env

**Part B — Add MPS-to-CPU fallback logic in tribe_loader.py:**

In `_build_model`, before calling `TribeModel.from_pretrained`, add a device validation step:

```python
import torch
import logging

logger = logging.getLogger(__name__)

def _build_model(cache_folder: Path, device: str) -> Any:
    cache_folder = cache_folder.resolve()
    os.environ["HOME"] = cache_folder.as_posix()
    os.environ.setdefault("XDG_CACHE_HOME", (cache_folder / ".cache").as_posix())
    os.environ.setdefault("HF_HOME", (cache_folder / "huggingface").as_posix())

    # Validate device — fall back to CPU if MPS requested but unreliable
    if device == "mps":
        if torch.backends.mps.is_available():
            logger.warning("MPS available but TRIBEv2 inference stalls on MPS — falling back to CPU")
        device = "cpu"
    elif device == "cuda" and not torch.cuda.is_available():
        logger.warning("CUDA requested but not available — falling back to CPU")
        device = "cpu"

    from tribev2.demo_utils import TribeModel

    model = TribeModel.from_pretrained(
        "facebook/tribev2",
        cache_folder=str(cache_folder),
        device=device,
    )
    return model
```

This ensures: (a) MPS always falls back to CPU because TRIBEv2 stalls on MPS, (b) CUDA falls back to CPU if unavailable, (c) explicit CPU works directly.

**Part C — Update inference.py to handle CPU tensors:**

In `backend/services/inference.py`, the `preds.cpu().numpy()` call is already correct for CPU (cpu().numpy() is a no-op on CPU tensors). No change needed here, but verify this by reading the file. The `ThreadPoolExecutor(max_workers=1)` is also fine for CPU inference.
