# Phase 1 — UI Design Contract

> Visual and interaction contract for BrainX. Generated by gsd-ui-researcher.
> Phase 1 is backend-only (no frontend surfaces ship in this phase), but this
> document is the single design system source of truth consumed by Phases 4 and 5.
> All frontend phases MUST reference this contract. Do not re-specify what is
> declared here.

---

## Scope Note

Phase 1 has zero UI surfaces — it delivers a FastAPI backend, GPU queue, and
TRIBEv2 inference endpoints only. This UI-SPEC exists because the user requested
the design system be locked in a reusable file now, before any frontend work
begins. Phases 4 and 5 (frontend) inherit every section of this contract without
modification unless a later UI-SPEC explicitly overrides a specific field.

## Typography

All sizes in rem, rendered at browser default 16px base.

| Role | Size | px equiv | Weight | Line Height | Font | Tailwind |
|------|------|----------|--------|-------------|------|---------|
| Display | 2rem | 32px | 600 semibold | 1.2 | Inter (sans) | `text-4xl font-semibold leading-tight` |
| Heading | 1.25rem | 20px | 600 semibold | 1.3 | Inter (sans) | `text-xl font-semibold leading-snug` |
| Body | 1rem | 16px | 400 regular | 1.5 | Inter (sans) | `text-base font-normal leading-relaxed` |
| Label / Caption | 0.875rem | 14px | 400 regular | 1.4 | Inter (sans) | `text-sm font-normal` |
| Code / Monospace | 0.875rem | 14px | 400 regular | 1.6 | Roboto Mono | `font-mono text-sm` |

Rules:
- Only two weights in use: 400 (regular) and 600 (semibold). Do not introduce 500 or 700.
- Serif (Lora) is reserved for long-form explanatory copy in the simulation log view (Phase 2) and recommendation body text (Phase 3). Do not use Lora in nav, labels, or headings.
- Monospace (Roboto Mono) is reserved for: job IDs, activation score values, raw simulation log output, API response previews.
- All text uses `--foreground` on `--background` surfaces. On `--card` surfaces, use `--card-foreground`.

## Color

60/30/10 contract — dark mode values (primary theme):

| Role | CSS Variable | Dark Mode Value | Usage |
|------|-------------|-----------------|-------|
| Dominant (60%) | `--background` | `oklch(0.21 0.02 226.02)` | Page background, layout shell |
| Secondary (30%) | `--card` / `--sidebar` | `oklch(0.23 0.03 218.18)` / `oklch(0.19 0 0)` | Cards, sidebar, nav panels, modals |
| Accent (10%) | `--primary` | `oklch(0.72 0.12 210.36)` | See reserved list below |
| Destructive | `--destructive` | `oklch(0.64 0.21 25.39)` | Destructive actions only (see copywriting) |

Accent (`--primary`) is reserved for exactly these elements — nothing else:
1. Primary CTA button background (e.g., "Run Analysis", "Submit")
2. Active nav/sidebar item indicator
3. Job status badge: RUNNING state pill
4. Focus ring (`--ring`) on all interactive elements
5. Progress bar fill during inference polling
6. Circuit activation score bar: highest activation level (Very High)

Muted accent usage (`--accent` / `--accent-foreground`):
- Hover state on secondary buttons
- Selected state on persona cards
- Subtle highlight on code/log preview backgrounds

Second semantic color (`--muted` / `--muted-foreground`):
- Empty state copy
- Placeholder text in form inputs
- Disabled element foreground
- Supporting annotations in brain map ROI table

Chart tokens (`--chart-1` through `--chart-5`) are reserved for the 5-circuit
activation color scale. Assignment:
- `--chart-1`: Attention circuit
- `--chart-2`: Cognitive Load circuit
- `--chart-3`: Emotional Response circuit
- `--chart-4`: Memory Encoding circuit
- `--chart-5`: Reward circuit

## Copywriting Contract

Consumer-friendly language mandated by D-10 (locked decision from CONTEXT.md):
no Brodmann codes, no anatomical subcortical terms anywhere in UI copy.

| Element | Copy | Notes |
|---------|------|-------|
| Primary CTA — submit analysis | "Run Analysis" | Phase 4 upload form submit button |
| Primary CTA — demo | "Explore Demo" | Phase 5 demo entry point |
| Primary CTA — re-open session | "View Results" | Phase 5 session history |
| Job status: PENDING | "Waiting in queue" | With position indicator if queue > 1 |
| Job status: RUNNING | "Running analysis..." | With elapsed time counter |
| Job status: DONE | "Analysis complete" | Transitions to results view |
| Job status: ERROR | "Analysis failed — [reason]. Try again or contact support." | Reason comes from API error_message field |
| Model status: healthy | "Model ready" | GET /model-status = loaded |
| Model status: loading | "Model loading..." | During startup |
| Model status: error | "Model unavailable. Restart the server to continue." | Startup failure per D-08 |
| Empty state — no sessions | "No analyses yet. Upload a UI screen or paste text to get started." | Phase 5 history view |
| Empty state — no persona | "No persona saved. Define who is using your design to get started." | Phase 4 persona section |
| Empty state — brain map | "Brain map will appear here after analysis completes." | Phase 4 results panel |

| Destructive — delete session | "Delete Session": "This session and all its results will be permanently deleted. This cannot be undone." | Confirm dialog |

## Interaction Contracts

### Job Polling (INFRA-03)

- Poll `GET /jobs/{id}` every 3 seconds while status is PENDING or RUNNING.
- On DONE: stop polling, transition UI to results view with a subtle fade-in (200ms).
- On ERROR: stop polling, show Alert component with error message from API.
- Never use websockets in Phase 4 — polling only per D-05/INFRA-03.
- Display elapsed time as "Xm Xs" next to the RUNNING badge.

### 3D Brain Visualization (FE-01)

- Render fsaverage5 GLTF mesh via `@react-three/fiber`.
- Vertex color attribute updated directly on the BufferGeometry — do NOT trigger React re-renders on activation data updates.
- Camera: orbit controls enabled, auto-rotate disabled by default, re-enable on user idle (5s).
- Canvas background: `--background` color (transparent canvas over page surface).
- Loading state: use `<Skeleton>` placeholder at identical dimensions until GLTF loads.

### File Upload (CONT-01, CONT-02)

- Accept: `image/jpeg`, `image/png`, `image/webp`.
- Maximum: 5 files per upload (CONT-01 cap).
- Drag-and-drop zone uses dashed `--border` color border at 2px, switches to solid `--primary` on active drag.
- Each uploaded screen shows a thumbnail card with a remove button (icon-only, 44px touch target).
- File validation errors appear inline below the dropzone as `--destructive` colored text.

### Persona Form (PERS-01 through PERS-04)

- Cognitive state fields (attention span, stress level, tech literacy) use `<Slider>` with labeled stops.
- "Save Persona" is a secondary button (outlined, not filled). "Use Persona" is the primary button.
- Saved personas display as `<Card>` items in a horizontal scroll row. Selected persona has a `--primary` ring.

### Activation Score Display (BRAIN-04)

- All scores displayed as 0–100 integers. Raw float activation values from API are multiplied by 100 and rounded.
- Each score row in the ROI table shows: circuit name + qualitative label + progress bar fill using chart token.
- Hover tooltip on circuit name shows: cortical proxy region name (e.g., "OFC, ACC" for Reward). This is the only place anatomical terms appear — inside a hover tooltip, not in primary UI.

## Phase-Specific Notes

### What Phase 1 Must Set Up (Backend, Not UI)

Phase 1 delivers no UI surfaces, but the executor MUST prepare the frontend
scaffolding so Phase 4 can build immediately:

1. Initialize React/Vite or Next.js frontend project in `frontend/` directory.
2. Run `npx shadcn init` with the custom preset derived from this UI-SPEC.
3. Copy the CSS custom properties block from this document into `globals.css`.
4. Install font dependencies: `inter`, `lora`, `roboto-mono` (via Google Fonts or npm packages).
5. Configure Tailwind with the color and font mappings from this document.
6. Add `components.json` to version control.
7. Do NOT install shadcn component slugs yet — Phase 4 installs only what it needs.

This scaffolding is a Phase 1 task alongside the backend work, not deferred.

### What Phases 4 and 5 Inherit

- Full color token set (light and dark) — no re-specification needed
- Full typography scale — no re-specification needed
- Full spacing scale — no re-specification needed
- Full component inventory — install per phase needs, not all at once
- All copywriting — extend with phase-specific empty/error states as needed, but never replace what is already declared here
